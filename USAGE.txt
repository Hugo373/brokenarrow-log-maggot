Broken Arrow Log Tool / 断箭日志工具
====================================

English
-------
Read-only analyzer. It reads GameLogs and writes a report only when requested.
It does not access game memory, inject into the game, install input hooks, or modify Broken Arrow files.

Scan historical logs:
  python ba_tool.py scan

Write a JSON report:
  python ba_tool.py scan --json scan-report.json

Monitor the newest log live:
  python ba_tool.py watch

Use another log directory:
  python ba_tool.py --dir "C:\\path\\to\\GameLogs" scan

The default directory is the Steam installation used during development.
Press Ctrl+C to stop live monitoring.

Current implementation:
- Parses the persona name, lobby entry/exit, lobby players, battle start, FID,
  roster rows, room-client fallback rows, deck, total points, connection duration,
  and match termination.
- Reads historical files as UTF-8 and replaces malformed bytes safely.
- Live mode reads only bytes appended since the previous poll.
- Bot IDs remain negative and are not silently discarded.

Player index and match analysis / 玩家指数与对局分析
-------------------------------------------------
English:
- Live mode waits briefly for the roster to settle, then queries each human player.
- It uses the public endpoints `/api/analysis/player` and `/api/analysis/match`.
- Player indices come from the scoring engine in `scoring.py`: continuous
  team-relative components over 12 valid ELO-changing matches, recency decay,
  party down-weighting, Bayesian shrinkage and a 90% confidence interval
  (details in ARCHITECTURE.md). The cosine ranking formula remains available
  as the reference implementation `maggot_index`.
- At match end, a bilingual human-readable report is printed.
- Bots are not queried. API failures are shown as `API unavailable`.
- This can generate many public API requests: roughly one profile request plus
  up to twelve match requests per player. Respect the service's rate limits.

中文：
- 实时模式会短暂等待玩家列表稳定，然后查询每名真人玩家。
- 使用公开接口 `/api/analysis/player` 和 `/api/analysis/match`。
- 玩家指数由 `scoring.py` 评分引擎产出：12 场 ELO 有效对局上的队内连续相对成分、
  时间衰减、组排降权、贝叶斯收缩与 90% 置信区间（详见 ARCHITECTURE.md）；
  余弦名次公式仍保留为参考实现 `maggot_index`。
- 对局结束时输出双语、人类可读的对局分析。
- 不查询机器人；API 失败会显示 `API unavailable / API不可用`。
- 该功能可能产生较多公开 API 请求：每名玩家约 1 次档案请求和最多 12 次对局请求，
  请遵守服务端限流规则。

Disable network lookups:
  python ba_tool.py --dir "C:\\path\\to\\GameLogs" watch --no-stats

Use a compatible API mirror:
  python ba_tool.py watch --stats-api "https://example.invalid"

Web UI / 网页界面
----------------
English: start `python web_ui.py`. Open `http://127.0.0.1:8765` in a browser.
The dashboard shows watcher state, current roster, per-player index progress,
cache counters, API failures, and the final bilingual report.

中文：运行 `python web_ui.py`，然后在浏览器打开 `http://127.0.0.1:8765`。
仪表板会显示监控状态、当前名单、玩家指数获取进度、缓存统计、API 失败次数以及双语局后报告。

Offline mode / 离线模式：
  python web_ui.py --no-stats

Options / 参数：
  --port N          preferred port; the next 19 ports are tried when taken / 占用时自动尝试后续 19 个端口
  --no-browser      do not auto-open the dashboard / 不自动打开浏览器
  --daily-limit N   rolling 24h public API budget (default 300); cache hits cost nothing
                    / 24 小时滚动 API 配额（默认 300）；命中缓存不计费

Smoke test / 冒烟测试（发布前必跑）：
  python smoke_test.py

The API layer uses persistent JSON cache, per-endpoint TTLs, fresh/stale distinction,
bounded retries, exponential backoff, a tiered circuit breaker, rolling daily quota,
human-verification page detection, and stale-cache fallback. It never sends log
contents to the API.
接口层使用持久化 JSON 缓存、按接口分层的有效期、有效/过期区分、有限重试、指数退避、
分级熔断、24 小时滚动配额和人机验证页面识别，并在失败时回退过期缓存；
不会向 API 发送日志内容。

中文
----
这是一个只读分析工具。它只读取 GameLogs；只有在明确请求时才写入报告。
它不会访问游戏内存、注入游戏进程、安装输入钩子，也不会修改《断箭》的游戏文件。

扫描历史日志：
  python ba_tool.py scan

生成 JSON 报告：
  python ba_tool.py scan --json scan-report.json

实时监控最新日志：
  python ba_tool.py watch

指定其他日志目录：
  python ba_tool.py --dir "C:\\path\\to\\GameLogs" scan

默认目录是开发期间使用的 Steam 游戏安装目录。
按 Ctrl+C 可以停止实时监控。

当前实现：
- 解析玩家名、大厅进入/退出、大厅玩家、战斗开始、FID、玩家列表、
  GameRoom 客户端备用列表、卡组、总分、连接时长和对局结束事件。
- 历史日志按 UTF-8 读取，遇到损坏字节时安全替换。
- 实时模式只读取上次轮询之后追加的字节。
- 保留机器人的负数 ID，不会静默丢弃。
